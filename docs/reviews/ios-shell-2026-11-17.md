# Independent review: iPhone shell and internal TestFlight

Reviewed by a separate agent in an isolated worktree. Initial implementation: `05d14c0`. Follow-up review includes
`e1889a0` (cancellation), `c3b6651` (regressions), `f7d6835` (Swift manifest), `7949904` (local test concurrency),
`8ea544b` (released no-setup page) and `a869778` (bounded hung-request test), plus the test corrections recorded here.
No real signing key, Apple account, upload or review submission was used by the reviewer.

## Findings and resolutions

1. **Cancelled signing skipped cleanup.** A synthetic release reaching an archive removed its inputs on ordinary
   failure, but SIGTERM left the private directory, temporary keychain, installed profile and changed search list.
   The runner now handles signals, cancels asynchronous children/requests and performs cleanup afterward. Tests
   execute copied release modules with generated dummy credentials and stub Apple/security commands; they also
   assert that build subprocesses inherit no signing secret values and that the exact original search list returns.
2. **Packaging and workflow expectations were too weak.** The asset test used the exported implementation allowlist
   as its oracle, so adding `.env` passed. The workflow check searched for substrings, so appending `|| true` passed.
   Tests now independently name the six permitted assets and require the complete trusted-main predicate.
3. **The signed-IPA boundary lacked regression coverage.** New filesystem/tool-stub tests reject incorrect identity,
   minimum OS, device family, build number, page bytes, provenance, local URL and signature. A copied release process
   also rejects a substituted page, proving it actually invokes verification before reporting export success.
4. **Offline proof initially bypassed real startup and failed to block traffic.** The original XCTest instantiated a
   separate controller; a second test now checks the real application window/root and its loaded page. The original
   fetch probe could fail solely because of CORS. A `no-cors` probe exposed that Capacitor replaces its content
   controller after `webViewConfiguration(for:)`. Rules now attach in `webView(with:configuration:)`, after that
   replacement. Both tests pass, and removing the blocking rules makes the offline test fail at its network assertion.
5. **The existing request-timeout test assumed startup completed within a fixed settle.** Its new bounded poll keeps
   the loading, timeout-message and successful-refresh assertions. Disabling the production abort timer still fails
   with `not stuck loading` after about 6.6 seconds, so the correction does not mask a stuck request.

## Verification and limits

- Fourteen focused JavaScript tests passed with the repository virtual clock: shell, release, documentation and
  runner checks. The revised hung-request case also passed independently before its abort-path mutation.
- Xcode 27.2 / iPhone 18 Pro simulator: both startup and offline tests passed against the no-setup page from
  `8ea544b`, with the corrected blocker injection (two tests, zero failures). Root-controller and blocker mutants
  each produced the intended XCTest assertion failure, not a compilation or simulator startup failure.
- A clean `ios:sync` regenerates the iOS 27 Swift manifest compatibly; the reviewed build resolves Capacitor 8.6.2.
- The review approves the shell/release behavior and regression coverage. Full committed-HEAD CI, GitHub checks,
  real signing/upload verification and physical iPhone acceptance remain separate release requirements.
- Live Activity, AlarmKit, native offline snapshots, Wi-Fi, geofences and Siri are outside this implementation;
  unresolved engine/page/proxy contracts remain tracked in issue #58. This is not approval of those future features.
